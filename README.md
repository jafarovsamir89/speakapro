# SpeakAPro 🎧🌍

**SpeakAPro** — Android-приложение для синхронного перевода окружающей речи прямо в наушники пользователя.

Главный сценарий: пользователь находится в другой стране, надевает Bluetooth/проводные наушники, нажимает **«Слушать»**, а телефон через свой микрофон улавливает речь окружающих и почти сразу воспроизводит перевод в наушниках.

> Статус: **MVP / начало разработки**

## Главный принцип архитектуры

**Для MVP SpeakAPro не использует и не требует собственного сервера, VPS, Docker, базы данных или backend-приложения.**

Поток данных максимально короткий:

```text
Человек рядом говорит
        ↓
Микрофон телефона
        ↓
Android AudioRecord
        ↓
PCM 16-bit / 16 kHz / mono
        ↓
Gemini Live API
        ↓
переведённый PCM audio
        ↓
Android AudioTrack
        ↓
Bluetooth / проводные наушники
```

Это уменьшает сложность разработки и потенциальную задержку.

## Цель MVP

Сделать один действительно хороший режим **«Слушаю»**:

- захват окружающей речи микрофоном телефона;
- потоковая отправка аудио в Gemini Live;
- получение переведённого аудио;
- немедленное воспроизведение перевода в наушниках;
- отображение оригинального текста и перевода;
- Start / Stop;
- корректная обработка ошибок сети и аудио.

## AI-модель

На старте проект ориентирован на Live Translation API и модель:

```text
gemini-3.5-live-translate-preview
```

Идентификатор модели должен находиться в конфигурации, чтобы его можно было заменить без переделки аудиоподсистемы приложения.

## API key в development

Во время разработки приложение подключается к Gemini напрямую.

Ключ хранится только локально на компьютере разработчика, например в:

```text
local.properties
```

или другом локальном secrets-файле, который обязательно исключён из Git.

Нельзя:

- коммитить API key в GitHub;
- писать ключ прямо в Kotlin-коде;
- помещать production key в `strings.xml`;
- публиковать APK/AAB с постоянным открытым ключом внутри.

## Production-защита

Этот вопрос **не блокирует создание MVP** и решается после того, как real-time перевод заработает на физическом Android-устройстве.

При подготовке публичной версии рассматриваем в таком порядке:

1. защищённый Google/Firebase client gateway с App Check, если он поддерживает выбранную Live Translation модель и нужный API-контракт;
2. если для конкретной Live-модели требуется ephemeral token — маленькая serverless-функция только для выдачи короткоживущего токена;
3. собственный постоянно арендованный VPS рассматривается только если когда-нибудь появится отдельная продуктовая необходимость.

Даже во втором варианте аудиопоток должен идти **напрямую с телефона в Gemini**, а не через наш сервер.

## Первый пользовательский сценарий

1. Пользователь открывает SpeakAPro.
2. Даёт разрешение на микрофон.
3. Подключает наушники.
4. Выбирает язык, на котором хочет слышать перевод.
5. Нажимает **«Начать перевод»**.
6. Телефон слушает окружающую речь.
7. Перевод начинает звучать в наушниках.
8. На экране показываются оригинал и перевод.
9. Пользователь нажимает **«Остановить»**.

## Принципы MVP

- **Минимальная задержка важнее количества функций.**
- Сначала доказать работоспособность real-time audio pipeline.
- Не добавлять регистрацию, подписки, социальные функции и сложную навигацию до рабочего перевода.
- Не арендовать сервер только ради архитектуры.
- Не сохранять raw audio по умолчанию.
- Ошибка сети не должна зависать приложение.
- UI должен быть удобен одной рукой.
- Сначала стабилизировать режим «Слушаю», затем делать двусторонний разговор.

## Не входит в первый MVP

- iOS;
- собственный backend;
- VPS/сервер;
- база данных;
- аккаунты и подписки;
- офлайн-перевод;
- история аудиозаписей;
- групповые комнаты;
- распознавание конкретных собеседников;
- автоматический двусторонний режим разговора;
- облачное хранение транскрипций.

## Следующие этапы

После стабильного MVP:

1. режим **«Разговор»** — собеседник → наушники, пользователь → динамик телефона;
2. push-to-talk для ответа пользователя;
3. локальный VAD и оптимизация трафика;
4. выбор голоса и скорости воспроизведения, если API это позволяет;
5. offline fallback;
6. production-защита доступа к Gemini без постоянного открытого ключа в APK;
7. при необходимости авторизация и подписки;
8. iOS-версия.
